# Pixel 9a source product integration

This subtree supplies a real Soong `android_app` named **AIHome**, using the existing
0.2.0 Java/resources as its only app source of truth. It is compiled into the
product image as an ordinary app. It requests no permissions, has no platform
certificate or shared UID, and is not a privileged app. The normal OS release
signing process must replace its development certificate; the separately built
debug APK cannot update a release-signed system app.

The official ChatGPT APK and Google Play are not bundled here. Install them using
the supported sandboxed Play path in the same profile after an authorized device
installation. Existing ChatGPT account features remain implemented by the official
app. No MCP or remote-control service is introduced by this product integration.

## Preparation and exact product inclusion

```sh
python3 scripts/prepare-os-product.py --output /tmp/aifirst-product
```

The helper emits the **contents** of `vendor/adevtool/config/mk/aifirst`, not its
ancestor directories. It inserts the manifest package normally supplied by Gradle,
copies canonical app sources/resources and the repository license, and fixes file
modes. It rejects source symlinks, an occupied output, unreviewed app version changes
and expanded manifest permissions. Its stdout contains per-file hashes; it never
downloads APKs, signs artifacts or modifies an OS checkout/phone.

The root integration assembler consumes these bytes and the three canonical
patches described in `upstream-contract.json`. All additions belong to the already
signed `vendor/adevtool` source project and become reviewed Git patch content, not
untracked generated-vendor exceptions. Do not copy this directory directly into a
release checkout and bypass source verification.

The pinned upstream product chain is:

```
vendor/google_devices/tegu/tegu.mk  (generated by adevtool)
  -> vendor/adevtool/config/mk/google_devices/device/tegu/device.mk
       -> vendor/adevtool/config/mk/aifirst/aifirst.mk
            -> PRODUCT_PACKAGES += AIHome
```

Only the six-line, source-controlled `tegu/device.mk` is patched to add the final
inheritance. The generated `tegu.mk` remains owned by adevtool. `aifirst.mk` exposes
its Soong namespace and adds product resource overlays. Existing Launcher3/Quickstep,
Settings, dialer, messaging, Clock, keyguard and notification shade remain included;
the product does not override/remove their modules or change the recents provider.

## Initial HOME behavior and recovery

The pinned PermissionController HOME role has no configurable default holder.
Its `HomeRoleBehavior` fallback chooses the unique highest-priority eligible Home;
ties produce no choice. Raising our ordinary app's intent priority would not work:
the pinned framework `ComponentResolver` caps non-privileged app priority to zero.
This integration therefore makes three explicit changes:

1. A new empty framework string, `config_defaultAIFirstHome`, leaves nonparticipating
   products unchanged. The product resource overlay sets it to `dev.aifirst.launcher`.
2. The HOME role's XML declares `defaultHolders="config_defaultAIFirstHome"`.
   Existing RoleController code uses this only for a newly added role with no current
   holder. It does not replace an existing user-selected launcher on every boot/update.
   Qualification checks and the existing Home fallback stay intact.
3. The ordinary APK's `chatgpt_on_home_default` resource stays false, preserving its
   opt-in behavior. Only the OS product overlays it to true. An explicitly saved
   preference always wins over this default.

Thus a fresh product profile is intended to choose AI Home as its initial HOME
holder; an unlocked HOME intent can hand off to official ChatGPT when installed.
Missing/unlaunchable ChatGPT leaves local controls visible. The app icon and Phone
controls Quick Settings tile explicitly open controls instead of rerouting. The
user can disable ChatGPT-on-Home or choose Launcher3 using the full Android Settings.
The code does not start Voice automatically, embed ChatGPT, bypass the lock screen,
or launch on arbitrary activity resume events. The OS gesture integration is a
separate framework patch with its own validation.

## Verification and release conditions

Sixteen preparation and mutation-boundary tests pass locally. The three canonical patches
have exact project/commit/base-file SHA-256 contracts and were checked/applied to
small exact-commit source snapshots. The staged package manifest/resources were
compiled and linked with Android 35 `aapt2`, and all staged Java compiled with
Java 17 source/target against that public SDK. The linked resource dump confirms
`chatgpt_on_home_default=true`. This source/resource smoke check does **not** prove this Soong module,
full resource overlay assembly, initial HOME role grant, Quickstep coexistence, or
a bootable image. Those require the complete pinned OS tree on the prepared runner,
followed by approved physical testing on the development Pixel.

Keep the production lock blocked until the rest of the OS source/vendor provenance,
keys, our updater endpoint and release evidence are established. Product integration
does not authorize bootloader unlock, installation, wipe, relock or any phone change.
